# Software knowledge

Established knowledge of the software, in four layers. Follow
[Artifact Driven](../governances/artifact-driven/knowledge.md) for ownership,
citation direction and Flow-rule adoption prerequisites.

This folder holds the sample: a small library lending
service, written from system down to contracts. A project replaces it with
its own knowledge and keeps the shape.

- [System](system/README.md): purpose, actors, services, clients, system-wide
  requirements and glossary.
- [Goals](goals/README.md): business outcomes and their success criteria.
- [Flows](flows/README.md): knowledge that crosses artifacts, the edges.
- [Artifacts](artifacts/README.md): one artifact per domain, each served by
  one service; the nodes.
