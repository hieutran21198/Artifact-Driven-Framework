The framework

The framework turns the governance of Artifact Driven into tools that developers and AI agents use. It has these parts:

  • Governance: the rules of the method.
    • Knowledge: the layers (system, goals, flows, artifacts), IDs, citations, contracts and diagrams.
    • Workflow: the steps from an issue to merged knowledge and code.
    • Team: the parts, their owners, and the roles that do each step.
    • Done: what a change needs before it counts as done.
    • Decisions: why each choice was made, and what it costs.
  • Runbooks: step-by-step procedures for each kind of change.
    • Shape a need into a goal.
    • Add or change a goal,a flow, an artifact rule or a contract.
    • Describe a client, start an artifact, move or split knowledge, remove an operation.
    • Handle a reported defect, fix stored data, report a release, check the docs.
  • Scripts: checks that keep the knowledge consistent, and an impact analysis.
    • check_structure: every folder has a README.
    • check_docs: links, anchors, IDs, citation direction, and scenarios that name what starts them.
    • check_tests: tests name only IDs the knowledge holds.
    • impact: what a change touches; with --down, --stats, --coverage, --fragile and --questions.
    • site: one HTML page that shows how goals, flows and artifacts link.
  • Install script: creates a workspace with all of the above in one command.
    • install.sh <folder> [ref], from any branch, tag or commit of the framework.
    • The new workspace starts with the library sample, written from system down to client needs.

From these parts, each workspace gets:

  • CONTRIBUTING.md: how to make and check a change.
  • AGENTS.md and CLAUDE.md: the instructions coding agents read.
  • Agent definitions: knowledge writer, contract designer, client writer, implementer, defect investigator and reviewer.
  • Skills: software-knowledge, defect-triage and backend-service.

A developer and a coding agent then follow the same rules.

The files of a workspace:

my-workspace/
├── README.md
├── CONTRIBUTING.md
├── AGENTS.md
├── CLAUDE.md
├── artifact-driven.json          configuration the scripts read
├── .agents/
│   ├── agents/                   agent definitions
│   └── skills/                   skills
├── .claude/                      links to .agents
├── docs/
│   ├── architecture/
│   │   └── domain-map.md         each domain and the service that serves it
│   ├── governances/
│   │   └── artifact-driven/      governance and runbooks
│   ├── coding-standards/
│   ├── infrastructure/
│   ├── principles/
│   └── software-knowledges/
│       ├── system/               context, requirements, glossary, openapi.yaml
│       ├── goals/                <goal>.md
│       ├── flows/                <flow>.md, <flow>.openapi.yaml
│       └── artifacts/
│           └── <artifact>/       README.md, specification.md, openapi.yaml,
│                                 service.md, <client>.md
├── scripts/                      checks, impact, site
├── services/                     one clone per service
├── apps/                         one clone per client
└── e2e/                          end-to-end tests
