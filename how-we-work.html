Break down the requirement

Requirement: a member reads books at home, borrows up to the loan limit, only from the shelf, for 14 days, and brings them back; a late book is overdue.

  1. Make the need clear

    Remind members before the due date.

    Product owner
    describe the need, pick one option
    Solution architect
    list the rules it touches, write the options, ask about the pick
    Developer
    give the cost of each option

    Runbook: shape a need into a goal

    Issue · members bring books back late
    Holds today→Due in 14 days. A book not back by then is overdue. A member with an overdue book cannot borrow.
    Options→Remind before the due date: adds a notice. Shorter loans: changes the loan period. Block borrowing: a rule does it already.
    Chosen→Remind before the due date
    Questions→How long before? Again when it is overdue?

  2. Write the goal

    A member can borrow a book and sees when it is due.

    Product owner
    gather information, write the criteria, approve the goal
    Solution architect
    ask what is unclear, one question at a time
    Tests
    one end-to-end test per criterion
    Diagram
    a flowchart of its flows

    Runbook: add or change a goal

    Goal · Borrow a book
    • A member borrows an available book and sees when it is due.
    • A book is on loan to one member at a time.
    • A member never holds more books than the limit.

  4. Pull out the rules

    Only a book on the shelf can be lent.
